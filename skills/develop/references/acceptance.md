# 分类验收

Select acceptance checks from project context and change risk; no universal checklist is mandatory. 先从项目现有 README、测试、CI 和规格查明命令及基线。用与改动风险相称的最高行为接缝验证；单元、契约和端到端互补，不为凑数量重复测试。选择以下相关项，可以组合。

## 所有软件变更

- 把验收要求映射到测试/人工证据；正常、失败、边界路径均按风险覆盖。
- 运行相关 lint、类型/静态检查、测试及必要构建。项目没有某种检查则说明，不为宣称齐全临时造空测试。
- 检查输入校验、错误处理、配置和敏感数据，不在日志或外部工具中暴露密钥及业务数据。
- 审查任务 diff、兼容性、依赖与回归范围；区分已存在失败和本次引入问题。
- 明确没有验证的环境/路径。缺设备、凭证或服务时保留局部证据，整体对应门槛标为阻塞或未执行。

## Web / H5 / 管理后台

- 用真实浏览器验证变更涉及的核心用户流程；检查加载、空态、错误态及相关窄屏/键盘交互。
- 从最新快照识别元素并操作，断言用户可见结果，检查相关控制台错误；用截图或 trace 留证，不能只打开首页。
- 若项目已有 Playwright 测试，优先运行它；交互调试复用 Playwright CLI Skill。截图只能证明当时画面，不证明完整功能。

## Native mobile / 健身 App

- 先确认实际栈：Web/PWA 走 Web；Swift/Kotlin/Flutter/React Native 等原生构建走本项，混合应用组合选择。
- 按项目工具链构建并在模拟器/设备运行关键行为：导航、表单、训练记录、持久化和恢复等，仅验收本任务涉及部分。
- 对相机、通知、传感器、健康数据、权限和后台任务使用平台对应测试；模拟器不支持的真机能力单列，不把模拟器通过冒充真机通过。
- 不使用 Playwright 的 WebView/H5 结果代替原生 UI/系统权限验收。不因普通健身功能自动安装模型服务或运行 RAGAS。

## AI / Agent / RAG（仅相关任务）

- 通用软件检查之外，验证工具选择与漏调用、工具契约、失败/超时降级、多轮状态隔离及注入边界。
- 有检索/证据回答时再验证召回、来源对应、无证据处理与回答质量。采用项目已有标注集/评分标准，不凭单条样例或模型自评宣称通过。
- 记录模型/提示词/数据版本、样本数、失败类别和成本/延时（仅当验收要求或风险相关）；调用收费模型/评测使用明确授权和预算。
- RAGAS 是相关项目的一种已有评测方式，不是所有 AI 项目、更不是所有软件的必经步骤。

## 集团小星专项（只在该项目加载）

从项目现有规格、answer-policy 和测试命令确认当前要求，不以本插件代替业务规则真源。涉及回答规则时沿用 paraphrase 371 + RAGAS 质量口径，Formal 99 作为旁路回归；具体数据/命令必须检查当前仓库，不能依据名称猜命令。

保护父子档 RAG、Rerank、证据审核、无状态 group_knowledge_answer 契约及多轮隔离。区分外层 Agent、回答 Skill、RAG 服务与 Codex 开发工具箱。没有新增业务授权时，不处理公网认证或上线。按当前代码核实各阶段实际能力，不把回答 Skill 交付视为外层原生工具路由也已完成。
