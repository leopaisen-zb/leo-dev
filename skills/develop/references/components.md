# 能力衔接

优先从当前会话的技能目录读取实际路径。安装插件不等于当前任务已重新加载技能；缺失时先查宿主实际可用工具，必要时让用户开新任务，不重复安装已有副本。本插件携带选定的原始方法资源与许可，不打包其工作流引擎，不自动安装外部依赖。

Load stage methods by gap, not by brand name. 按当前缺口选择规格、计划、实现、审查或交付做法；不因包内存在原文就视为该方法已使用，也不要求点名外部工作流才能开工。阶段内自己选实现和调试顺序。

| 缺口 | 衔接规则 |
| --- | --- |
| 澄清和规格 | 仅实质/模糊且缺合格规格时收敛；一次只问一个实质问题，已确认即复用，不再跑第二轮 |
| 需求/设计/任务 | 绑定已有工件；不自动批准实现 |
| 跨工件分析 | 只读分析不是批准，不运行 hooks |
| 实施计划 | 仅补仍缺的小步和验证命令；已有计划充分时省略重复方法，不重复产品决策 |
| 实施 | 优先既有测试接缝；配置/文档改动用相应校验，不伪造失败 |
| 审查 | 允许时对 diff 独立审查；脏工作区不要仅比较两个 commit 而忽略未提交改动 |
| 交付 | 当轮真实验证结果；push/merge/删除不是默认授权 |
| 界面 | 每阶段选最适合的能力，不因已安装而全量加载；保留产品已有设计系统 |
| 网页交互 | 独立命名会话，快照后操作，断言结果，截图/trace 取证；不关闭用户会话 |

包内原始来源以 [upstream/provenance.json](upstream/provenance.json) 为准，不依赖开发者 checkout。缺失则如实报告，不虚构已加载。开发者仓库中的 doctor 是只读路径检查，不属于这里承诺的包内业务验证命令。

若插件技能在本会话不可用但本地方法文件已存在，可以明确报告使用本地文件的兼容路径，并完整读取当前缺口所需内容。不要虚构外部工作流已被工具执行；通过读取技能指令后使用实际工具完成工作。

Do not inherit automatic worktree, commit, push, merge, hooks, telemetry, model, permission, or MCP changes. leo-dev commit may create a local git commit after independent review; that is this plugin's command, not inherited Superpowers git automation. 优先应用用户已选择的边界：设计已确认不重问；不要照抄外部关于模型和工具可用性的配置建议。使用当前平台实际工具定义。

不默认接入 Context7。它的外部服务与数据出站要单独确认；公开官方文档查询已能满足多数场景。不要同时引入第二套主流程。
