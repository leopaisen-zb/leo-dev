# 凭证据交付

在项目现有报告位置记录可复查证据；若没有约定，用本地任务规格旁的验证记录。不外发、不把内部文档复制到第三方服务。

每条检查记录：要求/行为、实际执行命令或人工步骤、环境、退出码/观测结果、证据位置、状态。采用这些明确状态：

- **通过**：本轮实际执行并符合验收要求。
- **失败**：实际执行但不符合验收要求。解释与本次改动是否相关及证据。
- **未执行**：没有运行，不推测结果。
- **阻塞**：缺少所需授权、依赖、设备或外部状态。说明已有尝试及需要用户决定什么。
- **不适用**：与本次类型/范围不相关，不算通过。写明原因。

未执行必须报告为未执行，不能报告为通过。

交付回复以结果开头，按需包含：

1. 交付内容及关键文件链接。
2. 实际通过的检查；失败、未执行或阻塞的门槛。
3. 剩余风险、使用/启动方式和必要的下一步。

小修复保持一两段，不强制长报告。复杂任务以报告链接承载细节。不把“代码已写”“插件已装”“测试通过”混为“产品可上线”；`integration-review` is not release-ready. Node 20、客户端加载、部署及其他没有实际运行的检查必须标为未执行。未请求部署就停在本地可验证交付。业务验收不通过时如实交付局部结果，不能标任务已全部完成。
