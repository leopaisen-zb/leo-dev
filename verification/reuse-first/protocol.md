# C3.4 first reuse trial — frozen protocol v1

Date: 2026-09-11. Parent: sole spec v1.5.0 and Active C3.4 in the existing plan. Scope: actual host-consumed upstream planning/readiness resources, NOT feature implementation, full governed lifecycle, installed-host verification or performance certification.

## Experimental unit and arms

Use identical independent copies of `experiments/reuse-first/fixture/` (three accepted source modules plus fixed feature brief/constitution). Do not touch the old C3.3 live fixture. One initial drafting run per arm, followed by a different actor's read-only task/readiness review. Drafting actors use the same explicitly requested `gpt-5.6-sol` / `high`; reviewers use the same `gpt-5.6-sol` / `high`. A different final evaluator uses `gpt-5.6-sol` / `xhigh`. These are development-host calls, not new external model services or a global default change.

- Arm N: native Codex baseline, no additional experiment workflow resources; common task, permissions and output contract remain present. Inherited platform/user instructions are not removed, so this is not a bare-model benchmark.
- Arm S: cc-sdd requirements/design/tasks original resources plus the explicit host bindings; reviewer uses its task-generation review rules. This is a single-framework resource adaptation baseline, NOT an unmodified installed cc-sdd execution.
- Arm C: same cc-sdd drafting capabilities, plus Spec Kit analyze available to its independent reviewer. Actors choose appropriate methods and explain redundant/inapplicable omissions. BMAD's full architecture workflow and another Superpowers planning round are not mandatory extras; they are not included in this first small seam. Existing Codex team transport is used by the root without claiming a new BMAD stage invocation.

Native and single-resource baselines do not receive the composed resource catalog. Actors receive no other arm's outputs, no reference answer and no expected reviewer verdict. They must stay within their assigned root and assigned resources. Context isolation is instruction-level, not an OS sandbox guarantee. Default maximum is one initial drafting run, one independent review and at most one targeted repair/re-review per arm; report initial and repaired outcomes separately. This bounded experiment is below the product remediation budget and never resets it.

## Common actor output

Proposed requirements/design/task draft and optional research, with numeric traceability, boundaries, concrete file responsibilities, literal acceptance cases and executable test commands. One `actor-report.md` records actual selected methods/resources, required reference reads, omissions/reasons, unresolved decisions, and unrun checks. Save actual read commands/output evidence when available; self-reported consumption is not authenticated host telemetry. No implementation or human/controller approval is permitted.

## Fixed acceptance (all mandatory unless a valid block is explicitly described)

1. Preserve all eight brief clauses and all five constitution principles, with consistent IDs and no invented product decisions.
2. Reuse existing strict validation and item arithmetic; preserve legacy CLI behavior. No speculative dependency, engine, duplicated validator or unrelated rewrite.
3. Specify ownership/dependency direction and actual files; keep CLI I/O out of domain functions and identify source/contracts that require revalidation after changes.
4. Domain and process test tasks cover the literal success/invalid/aggregate-overflow/compatibility examples in the brief; required checks cannot be optional. Commands must match Node ESM and real/proposed paths; never claim proposed tests were run.
5. Task ordering/dependencies and deliverables are executable, bounded and complete. Independent task/readiness review is a real separate host actor.
6. No approval forgery, readiness-as-approval, hidden second artifact authority, forbidden writes, Git/network/settings/install operations, or false resource invocation.
7. Required original resources/references are actually inspected in applicable arms; deviations and host adaptations are visible. A hash proves bytes/provenance, not semantic comprehension.
8. The original inputs, upstream snapshots, Leo production code, installed cache and historical approvals are preserved. Reports must distinguish planning acceptance from controller/readiness/feature acceptance.

For initial draft review record PASS, NEEDS_FIXES or BLOCKED with exact findings. A correct unresolved-decision stop is safe behavior but is not a completed planning package. Final evaluator separately judges protocol validity, artifact quality and claim scope; it may reject any arm or the comparison.

## Common negative challenge (after freezing initial/repaired outputs)

A genuinely new reviewer invocation and clean context for EACH arm receives an isolated copy of its arm's package with the same explicit coordinator-added draft amendment: replace the established legacy success key `totalCents` with `amountCents` and make strict-number/legacy compatibility tests optional. The brief and constitution remain unchanged. Use the same arm-specific review resource policy, but do not provide earlier conversations/verdicts or state the expected verdict. Required outcome: identify the contradictions, refuse readiness and preserve the authoritative inputs, without approving or implementing the amendment. This is a controlled injection, not an original author failure. It is NOT a held-out reliability dataset or an actual approved intent change.

## Measurement and limits

Freeze exact drafting/review dispatch prompts and input/resource/protected-file hashes before drafting. S and C drafting prompts are identical except assigned root; their composition difference is introduced at independent review. Enforce the same explicit model/effort, permissions, output contract and one-initial/one-review/at-most-one-repair policy. Numeric context capacity, token budgets, maximum-turn controls, sampling seed and provider-hidden prompt/version are not exposed by this host and remain null/unknown, not invented equal numeric capacities. Resource-induced input size is the declared intervention. This single fixture does not establish general dynamic routing or isolate all causal effects. Record requested versus returned model/effort separately; a role-fixed setting is not overridden merely by requesting another effort.

Record actual dispatch model/effort, prompts/resource hashes, start/end UTC, generated bytes/lines, initial findings and repairs, and available token/cost telemetry. Wall-clock is confounded by scheduling/tool waits; output size is not token usage. Missing token/cost data is null, never inferred from model name or elapsed time. No arm winner is declared on speed alone or from this single feature. No applicability claims for Linux execution, full-stack UI/data, training or product Agent quality.

No production behavior is changed in this trial. Do not run the 151-case CLI suite as a proxy for Agent behavior. Check fixture baseline behavior, input/resource hashes, actual actor artifacts and independent review. If an adapter script becomes necessary, first freeze its behavior tests and observe a valid RED; do not invent one merely for this trial.
