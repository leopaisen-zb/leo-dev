## Finding

### Important — valid empty design sources become permanently blocked after their request is committed

`packages/cli/src/changes/design-events.ts` requires
`designSourceBase64` to be a nonempty string. The existing producer,
`captureDesignReviewContext` in `packages/cli/src/changes/design-policy.ts`,
accepts every readable repository file and serializes an empty file as `''`.
The pre-Q1a consumer accepted that value because it checked only that it was a
string. There is no approved nonempty-design rule.

Reproduced against the built public CLI using an isolated Standard fixture with
an empty `design.md`: after normal initialization/routing/spec approval,
`transition --to design-review --design design.md --session producer` returned
exit 7 / `BLOCKED` with `Invalid persisted design-review event: request payload
does not match DesignReviewContext`; a following `status` also returned 7.
The request was already durably committed before the transition rendered its
state, so this both breaks legitimate historical/current data and leaves a
failed command with a durable write.

Fix: accept the empty string for `designSourceBase64` while retaining the
canonical Base64 round-trip validation. Add a public regression for an empty,
readable design source through transition and status/recovery.

`receiptSource.bytesBase64` is different: a zero-byte fresh-review source is
not a valid current writer form. `readReceipt` parses it and applies the
design-review schema before `claimDesignReceiptPlan` produces the envelope;
zero bytes parse to `undefined` and fail schema validation.
